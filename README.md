# AutoMark AI — Phase 1: Campaign Generation Pipeline

AutoMark AI is an **AI-powered pipeline** that takes a product image, a budget, and a campaign goal, and produces a complete **Meta (Facebook/Instagram) ad campaign bundle** — real generated ad images, ready-to-use copies, headlines, audience targeting, and budget allocation — all generated automatically using Large Language Models and Imagen 3.

> Phase 1 generates the campaign bundle only. It does **not** publish ads to Meta. Publishing is a future phase.

---

## What Does It Do?

You give it three things:

| Input | Example |
| --- | --- |
| Product image | `watch.jpg` |
| Budget (USD) | `500` |
| Campaign goal | `"get WhatsApp leads for luxury watch"` |

It asks you 4 product-specific questions, then returns a structured JSON bundle containing:

- **Product analysis** — what the product is, visual description
- **Campaign strategy** — platform (Instagram/Facebook/both), objective, tone
- **3 real ad images** — generated by Imagen 3 from a visual prompt
- **Ad creative** — 3 ad copies, 3 headlines, CTA button text
- **Media buying plan** — budget split per platform, daily budget, audience targeting, placements, bid strategy, estimated reach

## Architecture Overview

The system has **two graph variants** built on LangGraph:

### Streamlit Graph (full pipeline)

```
User Input (image + budget + goal)
        │
        ▼
┌──────────────────────────────────────────────────────────────┐
│               question_generator_node                         │
│  • Analyzes product image + goal with Gemini Vision           │
│  • Generates 4 product-specific questions                     │
│  • INTERRUPT → waits for user answers                         │
└──────────────────────┬───────────────────────────────────────┘
                       │  (answers appended to orchestrator prompt)
                       ▼
┌──────────────────────────────────────────────────────────────┐
│                   orchestrator_node                           │
│  • Analyzes image with Gemini Vision + Q&A context            │
│  • Decides platform, objective, tone, target audience         │
│  • Produces: campaign_plan                                    │
└──────────────────────┬───────────────────────────────────────┘
                       │
          ┌────────────┴────────────┐
          │  Fan-out (parallel)     │
          ▼                         ▼
┌──────────────────┐     ┌──────────────────────┐
│  creative_node   │     │  media_buying_node    │
│ • Writes 3 ad    │     │ • Allocates budget    │
│   copies         │     │   per platform        │
│ • Writes 3       │     │ • Defines audience    │
│   headlines      │     │   targeting           │
│ • Sets CTA       │     │ • Picks bid strategy  │
│ • Generates 3    │     │ • Estimates reach     │
│   real images    │     │                       │
│   (Imagen 3)     │     │                       │
└────────┬─────────┘     └──────────┬────────────┘
         │                          │
         ▼                          │
┌──────────────────────────────┐    │
│         review_node          │    │
│ • INTERRUPT → image review   │    │
│   (per-image approve/redo)   │    │
│ • INTERRUPT → text review    │    │
│   (copies, headlines, CTA)   │    │
│                              │    │
│  If text rejected → loops    │    │
│  back to creative_node       │    │
└──────────┬───────────────────┘    │
           │  (when all approved)   │
           └─────────┬──────────────┘
                     │  Fan-in
                     ▼
          ┌─────────────────────────┐
          │       merge_node        │
          │ • Validates all outputs │
          │ • Fixes CTA mismatches  │
          │ • Normalizes budget     │
          │ • Assembles final JSON  │
          └────────────┬────────────┘
                       │
                       ▼
          campaign_bundle.json  +  Streamlit UI
```

### CLI Graph (simplified, no interrupts)

```
START → orchestrator_node → [fan-out] → creative_node ─┐
                                      → media_buying_node ─┴→ merge_node → END
```

The CLI graph skips `question_generator_node` and `review_node`. Image generation still runs inside `creative_node` in both graphs.

## Node-by-Node Breakdown

### Node 0 — `question_generator_node` (`nodes/question_generator.py`)

**Role:** Warms up the pipeline by generating product-specific research questions before the orchestrator runs.

**How it works:**

1. Receives `image_path` and `goal` from the initial state
2. Calls **Gemini Vision** with the product image and a marketing analyst prompt
3. Parses the response into exactly 4 question strings (falls back to 4 generic questions if the LLM response is invalid)
4. Calls `interrupt()` — pauses the graph and sends the questions to the UI
5. Resumes when the user submits their answers

**LLM used:** Gemini Vision only (same as orchestrator — image inputs required).

**Only in:** Streamlit graph. Skipped in CLI.

**Interrupt payload:**

```json
{
  "stage": "questions",
  "questions": ["Q1?", "Q2?", "Q3?", "Q4?"]
}
```

**Resume payload expected:**

```json
{"answers": {"0": "answer", "1": "answer", "2": "answer", "3": "answer"}}
```

**Output:**

```json
{"questions": ["Q1?", "Q2?", "Q3?", "Q4?"], "user_answers": {"0": "A1", ...}}
```

---

### Node 1 — `orchestrator_node` (`nodes/orchestrator.py`)

**Role:** The "brain" of the pipeline. Analyzes the product image and builds the campaign strategy.

**How it works:**

1. Receives image path, budget, goal, and (in Streamlit) the user Q&A from state
2. Formats the Q&A answers as a structured block and appends them to the prompt
3. Calls **Gemini 2.5 Flash** (vision + text) to produce a JSON campaign plan

**LLM used:** Gemini Vision only — **no Groq fallback** (Groq does not support image inputs).

**Output — `campaign_plan`:**

```json
{
  "product_type": "Luxury Watch",
  "product_description": "An elegant gold-bezeled timepiece with a minimalist dial.",
  "platform": "instagram",
  "objective": "MESSAGES",
  "tone": "Sophisticated and exclusive",
  "target_audience_hint": "Affluent adults aged 28-50 interested in luxury lifestyle",
  "budget": 500.0,
  "currency": "USD"
}
```

**Platform selection logic (inside the prompt):**

- Luxury / fashion / lifestyle → `instagram`
- B2B / older demographic → `facebook`
- General consumer product → `both`

**Objective selection logic (inside the prompt):**

- Goal mentions leads / WhatsApp / DM → `MESSAGES`
- Goal mentions sales / purchase → `CONVERSIONS`
- Goal mentions awareness / reach → `AWARENESS`
- Anything else → `TRAFFIC`

---

### Node 2 — `creative_node` (`nodes/creative.py`)

**Role:** The "creative agency". Writes all ad text assets AND generates 3 real ad images.

**How it works:**

1. Checks if `state["feedback"]["creative"]` is set (redo pass from review) — if so, appends it to the prompt
2. Calls `call_llm()` to generate copies, headlines, CTA, and a `visual_prompt` string
3. Calls `generate_ad_images(visual_prompt, n=3)` using **Imagen 3** via the `google-genai` SDK
4. Stores the 3 images as base64 strings in `creative_output["generated_images"]`
5. If image generation fails (quota, network), logs a warning and stores an empty list — pipeline continues

**LLM used for text:** Gemini 2.5 Flash — **with Groq fallback**.

**LLM used for images:** Imagen 3 (`imagen-3.0-generate-002`) via `google-genai` SDK — **no fallback**.

**Output — `creative_output`:**

```json
{
  "copies": [
    "Elevate your style. Discover timeless craftsmanship made for the extraordinary.",
    "Every second is precious. Own the watch that honours yours.",
    "Luxury you can feel. Message us to claim yours today."
  ],
  "headlines": ["Luxury Redefined", "Own Your Moment", "Timeless Elegance"],
  "cta": "Send Message",
  "visual_prompt": "A close-up of a gold luxury watch on marble, soft studio lighting…",
  "generated_images": ["<base64_png_1>", "<base64_png_2>", "<base64_png_3>"]
}
```

**Copy rules enforced by the prompt:**

- Each copy: max 125 characters
- Each headline: max 40 characters
- CTA must match objective: `MESSAGES → "Send Message"`, `CONVERSIONS → "Shop Now"`, `TRAFFIC / AWARENESS → "Learn More"`

---

### Node 3 — `media_buying_node` (`nodes/media_buying.py`)

**Role:** The "media buyer". Runs **in parallel** with `creative_node`. Decides how to spend the budget and who to target.

**LLM used:** Gemini 2.5 Flash — **with Groq fallback**.

**Output — `media_output`:**

```json
{
  "budget_split": {"instagram": 1.0, "facebook": 0.0},
  "daily_budget_usd": 71.43,
  "audience": {
    "age_min": 30, "age_max": 65,
    "genders": ["all"],
    "interests": ["Luxury watches", "Horology", "High-end timepieces"],
    "income_tier": "top_10_percent"
  },
  "placement": ["feed", "stories", "reels"],
  "bid_strategy": "COST_CAP",
  "optimization_goal": "MESSAGES",
  "estimated_reach": {"min": 8000, "max": 20000},
  "reasoning": "Instagram-only for luxury product; COST_CAP for mid-range budget."
}
```

**Media buying rules enforced by the prompt:**

- `budget_split` values must sum to `1.0`
- `daily_budget_usd` = total budget ÷ 7 (assumes 7-day campaign)
- Bid strategy: budget < $200 → `LOWEST_COST`, $200–$1000 → `COST_CAP`, > $1000 → `BID_CAP`

---

### Node 4 — `review_node` (`nodes/review.py`)

**Role:** Human-in-the-loop quality gate. Runs after `creative_node`, before `merge_node`. Two sequential review phases, each using `interrupt()`.

**Only in:** Streamlit graph. Not present in CLI.

**Phase 1 — Image Review (loops until all images approved):**

- Sends the 3 generated images to the UI
- User approves each image individually, or provides per-image feedback for regeneration
- Rejected images are regenerated one by one using `generate_ad_images(visual_prompt + feedback, n=1)`
- Loop repeats until all 3 images are approved

**Phase 2 — Text Review (single interrupt):**

- Sends copies, headlines, and CTA to the UI
- User approves or provides a single feedback string
- If approved → returns `review_stage = "done"` → graph proceeds to `merge_node`
- If rejected → returns `review_stage = "redo_creative"` → graph loops back to `creative_node` with the feedback stored in state

**Interrupt payloads:**

```
Image review: {"stage": "image_review", "images": ["<b64>", "<b64>", "<b64>"]}
Resume with:  {"approved": [true, false, true], "feedback": {1: "make it darker"}}

Text review:  {"stage": "text_review", "copies": [...], "headlines": [...], "cta": "..."}
Resume with:  {"approved": false, "feedback": "Make the tone more urgent"}
```

---

### Node 5 — `merge_node` (`nodes/merge.py`)

**Role:** The "quality controller". Validates and fixes both sub-agent outputs, then assembles the final bundle.

**Guard (Streamlit only):** If `review_stage` is set but not `"done"` (meaning `media_buying_node` finished while review is still in progress), `merge_node` skips with `return {}`. The real merge runs only after `review_node` completes.

**What it validates and fixes:**

| Check | Fix Applied |
| --- | --- |
| Fewer than 3 copies | Pads with `"[Copy placeholder]"` |
| Copy exceeds 125 chars | Truncates to 125 chars |
| Fewer than 3 headlines | Pads with `"[Headline placeholder]"` |
| Headline exceeds 40 chars | Truncates to 40 chars |
| CTA doesn't match objective | Overrides CTA to the correct value, logs a warning |
| `budget_split` doesn't sum to 1.0 | Normalizes all values proportionally, logs a warning |

**Output — `campaign_bundle`** (final JSON):

```json
{
  "meta": {
    "generated_at": "2026-06-06T10:02:18Z",
    "llm_used": {"orchestrator": "gemini", "creative": "groq", "media_buying": "gemini"},
    "warnings": []
  },
  "product": {"type": "Luxury Watch", "description": "..."},
  "campaign": {"platform": "instagram", "objective": "MESSAGES", "tone": "..."},
  "creative": {
    "copies": [...], "headlines": [...], "cta": "Send Message",
    "visual_prompt": "...",
    "generated_images": ["<base64_png>", "<base64_png>", "<base64_png>"]
  },
  "media": {"budget_split": {...}, "daily_budget_usd": 71.43, "audience": {...}, ...}
}
```

## LLM Client (`llm_client.py`)

Three functions for three different model types:

### `call_llm(prompt, system_prompt, node_name)` — Text generation

Used by `creative_node` and `media_buying_node`.

```
Try Gemini 2.5 Flash
  ├── Success → return (text, "gemini")
  └── ResourceExhausted (429) or ServiceUnavailable (503)
        └── Try Groq llama-3.3-70b-versatile
              ├── Success → return (text, "groq")
              └── Failure → raise RuntimeError
```

### `call_llm_vision(image_path, prompt, system_prompt)` — Image + text

Used by `orchestrator_node` and `question_generator_node`. **No Groq fallback** (Groq is text-only).

### `generate_ad_images(prompt, n=3)` — Image generation

Used by `creative_node` and `review_node` (for per-image regeneration).

```
Call Imagen 3 (imagen-3.0-generate-002) via google-genai SDK
  ├── Success → return list of n base64-encoded PNG strings
  └── Failure → raise RuntimeError (caller decides whether to continue or abort)
```

Requires `google-genai` package (separate from the deprecated `google-generativeai` used for text/vision).

## Shared State (`state.py`)

All nodes communicate through a single `CampaignState` TypedDict. LangGraph passes this automatically.

```
START state         q_generator adds    orchestrator adds   sub-agents add      review adds         merge adds
───────────────     ───────────────     ─────────────────   ──────────────────  ──────────────      ──────────────
image_path      →   questions       →   campaign_plan   →   creative_output →   review_stage    →   campaign_bundle
budget              user_answers        llm_used            media_output        feedback
goal                errors              errors              llm_used
                                                            errors
```

**Special reducers:**

- `errors: Annotated[list, operator.add]` — errors from parallel nodes are **concatenated**, not overwritten
- `llm_used: Annotated[dict, _merge_dicts]` — dicts from parallel nodes are **merged**, not overwritten

**New fields added (vs original):**

| Field | Type | Added by | Purpose |
| --- | --- | --- | --- |
| `questions` | `list[str]` | question_generator_node | 4 product-specific questions |
| `user_answers` | `dict` | question_generator_node | User's answers keyed by index string |
| `feedback` | `dict` | review_node | `{"creative": str}` for text redo |
| `review_stage` | `str` | review_node / creative_node | Controls merge guard and routing |

## Graph Routing (`streamlit_graph.py`)

```python
# After question_generator_node:
question_generator_node → orchestrator_node  (always)

# After orchestrator_node (fan-out):
def _route_to_subagents(state):
    if orchestrator failed → "merge_node"   # short-circuit
    else → [Send("creative_node"), Send("media_buying_node")]

# After review_node (loop or proceed):
def _route_after_review(state):
    if state["review_stage"] == "redo_creative" → "creative_node"
    else → "merge_node"
```

The `MemorySaver` checkpointer enables interrupts by persisting state between Streamlit reruns, keyed by `thread_id` stored in `st.session_state`.

## Streamlit App (`app.py`)

5-stage UI driven by `st.session_state["ui_stage"]`:

| Stage | UI Shown | What Happens |
| --- | --- | --- |
| `setup` | File upload + budget + goal fields | Starts the Streamlit graph |
| `questions` | 4 generated questions with text inputs | Resumes graph with user answers |
| `image_review` | 3 ad images with per-image approve/feedback | Resumes graph; rejected images regenerated |
| `text_review` | Copies, headlines, CTA with approve/feedback | Resumes; rejection loops back to creative |
| `done` | Full campaign bundle + images + download button | Campaign complete |

**Session state keys:**

```python
st.session_state = {
    "thread_id":      str,   # UUID4 — identifies this campaign run in MemorySaver
    "ui_stage":       str,   # current stage name
    "interrupt_data": dict,  # payload from the latest interrupt
    "image_path":     str,   # path to the uploaded image (temp file)
    "final_state":    dict,  # final graph state after completion
}
```

## API Keys

**Gemini API Key (required — for text, vision, and image generation):**

1. Go to [https://aistudio.google.com](https://aistudio.google.com)
2. Sign in → click **Get API key**
3. Set `GEMINI_API_KEY=<your_key>` in `.env`
4. Free tier: ~15 RPM / 1,500 RPD for text+vision

**Groq API Key (optional — text fallback):**

1. Go to [https://console.groq.com](https://console.groq.com)
2. Sign up → **API Keys** → **Create API Key**
3. Set `GROQ_API_KEY=<your_key>` in `.env`
4. Free tier: ~30 RPM for `llama-3.3-70b-versatile`

> **Note on Imagen 3:** Image generation via `imagen-3.0-generate-002` may require billing enabled on your Google Cloud / AI Studio account. If quota is exceeded or billing is not set up, `creative_node` logs a warning and stores `generated_images: []` — the rest of the pipeline continues normally.

## Rate Limit Notes

The Streamlit pipeline makes up to **5 LLM calls per run** (more on redo passes):

| Call | Provider | Notes |
| --- | --- | --- |
| `question_generator_node` | Gemini Vision | 1 call |
| `orchestrator_node` | Gemini Vision | 1 call |
| `creative_node` (text) | Gemini / Groq fallback | 1 call per run |
| `creative_node` (images) | Imagen 3 | 1 call = 3 images |
| `media_buying_node` | Gemini / Groq fallback | 1 call |

| Provider | Free Tier Limit | Behavior When Hit |
| --- | --- | --- |
| Gemini 2.5 Flash | ~15 RPM / 1,500 RPD | Triggers automatic Groq fallback |
| Groq llama-3.3-70b | ~30 RPM | Raises `RuntimeError` |
| Imagen 3 | Billing-dependent | `generated_images` set to `[]`, pipeline continues |

## How to Extend

**Add a new node:**

1. Create `nodes/my_node.py` with a `my_node(state: dict) -> dict` function
2. Add prompt templates to `prompts/my_node.py`
3. In `streamlit_graph.py`: `builder.add_node("my_node", my_node)` and wire edges

**Add a new review step:**

1. Add a new `interrupt()` call inside `review_node` (before the final return)
2. Add a new `elif stage == "my_stage":` renderer in `app.py`

**Change the image generation model:**

- Edit `llm_client.py` — update `IMAGEN_MODEL` constant

**Change the LLM text model:**

- Edit `llm_client.py` — update `GEMINI_MODEL` or `GROQ_MODEL` constants

**Add a new output field:**

1. Return it from the relevant node
2. Add it to `CampaignState` in `state.py`
3. Include it in `campaign_bundle` inside `merge_node`
4. Display it in `_stage_done()` inside `app.py`
